# Architecture Decision Records

Esta pasta contém decisões arquiteturais importantes tomadas durante o desenvolvimento da Yuki.

Cada decisão relevante deverá possuir um registro próprio.

## Objetivo

Evitar que decisões importantes desapareçam no histórico de conversas.

Cada ADR deverá registrar:

* problema;
* contexto;
* alternativas;
* decisão;
* justificativa;
* consequências;
* status.

## Formato

```text
ADR-XXX — Nome da decisão

Status:
Data:

Contexto:

Problema:

Alternativas consideradas:

Decisão:

Justificativa:

Consequências:

Observações:
```

## Regra

Uma decisão registrada não significa que nunca poderá ser alterada.

Se uma decisão antiga for substituída, o ADR antigo permanece histórico e um novo ADR deverá explicar a mudança.

Isso mantém a evolução arquitetural rastreável.
